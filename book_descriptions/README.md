# Сбор сюжетных аннотаций в существующую Google-таблицу

Это **только дозаполнение описаний** уже присутствующих в таблице книг. Скрипт не собирает новые рейтинги, не создаёт позиции, не меняет цены, места, жанры, названия, авторов и заполненные аннотации.

Целевая таблица: https://docs.google.com/spreadsheets/d/1EhKpBf0VHW_kBVMgIwZv0_cE4-jtLhm9OYZMDGUqwpw/edit

## Что делает

1. Читает все листы, кроме «Сводка», «Новые площадки — сводка», **«Молодая гвардия»**.
2. Выбирает только строки с настоящими карточками книг и пустым описанием; технические строки об отсутствии рейтингов пропускает.
3. Ищет уже заполненное описание того же произведения в других листах по названию и автору; перестановка имени и фамилии автора допускается. Копирует вместе с подтверждённой ссылкой на источник.
4. Для остальных обращается к URL самой книги: обычный запрос → Firecrawl (если подключён) → Chromium/Playwright → поиск другой карточки в проверенных книжных доменах через Firecrawl (если подключён).
5. Записывает исключительно текст аннотации и ссылку на её источник, только в пустые ячейки. Перед записью перечитывает каждую целевую ячейку, чтобы не перезаписать ручные правки.
6. Создаёт отчёт по результатам в артефактах GitHub Actions. Шардирование распределяет работу по регулярным запускам и повторно пробует неудачные карточки.

По умолчанию расписание — **каждые 4 часа**, до 150 товарных страниц за запуск (и массовое копирование уже имеющихся аннотаций без обращений к сайтам). Скрипт не гарантирует получение описания, если страница недоступна ни одному из способов доступа; не выдумывает отсутствующее содержание.

## Настройка один раз

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте проект `book-descriptions` (либо выберите существующий). Включите [Google Sheets API](https://console.cloud.google.com/apis/library/sheets.googleapis.com).
2. Перейдите в [IAM → Service Accounts](https://console.cloud.google.com/iam-admin/serviceaccounts), создайте служебный аккаунт `book-sheets-writer`. Административные роли для Cloud ему не нужны. Откройте аккаунт → **Keys → Add key → Create new key → JSON** и скачайте ключ на свой компьютер. Если в организации создание ключей запрещено политикой безопасности, потребуется другая конфигурация авторизации, а не публичное размещение ключа.
3. Откройте [нашу Google-таблицу](https://docs.google.com/spreadsheets/d/1EhKpBf0VHW_kBVMgIwZv0_cE4-jtLhm9OYZMDGUqwpw/edit) → **Настройки доступа / Share**. Добавьте email аккаунта вида `book-sheets-writer@PROJECT_ID.iam.gserviceaccount.com` с правами **Редактор / Editor**. Снимите галочку оповещения. Других Google-документов он видеть не должен.
4. Откройте [GitHub Repository secrets](https://github.com/ARST113/movie_pars/settings/secrets/actions) → **New repository secret**. Имя: `GOOGLE_SERVICE_ACCOUNT_JSON`; значение: **всё содержимое скачанного JSON-файла**, включая фигурные скобки и переводы строк.
5. Для официального **облачного Firecrawl**, откройте [firecrawl.dev](https://www.firecrawl.dev/) → **Dashboard → API Keys**, получите отдельный ключ (обычно начинается с `fc-`) и поместите его туда же, в GitHub Repository secrets, под именем `FIRECRAWL_API_KEY`. Сборщик обращается непосредственно к **https://api.firecrawl.dev/v2**, локальный MCP-сервер нигде не используется.
6. Необязательно добавить `OPENROUTER_API_KEY`. Тогда описания будут **пересказаны в 2–4 предложениях** с сохранением подтверждённых фактов. Без него скрипт запишет нормализованную выдержку из явного поля описания товара (не более 1000 символов). Можно задать `OPENROUTER_MODEL`, например модель с небольшим расходом токенов. При ошибке генерации исходное описание не записывается, чтобы не подменять результат необоснованной аннотацией.
7. Расписание включено автоматически после добавления обоих ключей. Чтобы временно остановить сбор, в [GitHub Repository variables](https://github.com/ARST113/movie_pars/settings/variables/actions) добавьте `BOOK_DESCRIPTIONS_ENABLED=false`; значение `true` или отсутствие переменной разрешает запуск. Запуск вручную доступен в [Actions → Backfill book descriptions](https://github.com/ARST113/movie_pars/actions/workflows/book-descriptions.yml).

**Важно:** подключение приложения Firecrawl внутри ChatGPT не даёт GitHub Actions доступ к ключу пользователя: для автономных запусков ключ нужно добавить отдельно в GitHub Secrets. Не отправляйте ключи в чат, задачи GitHub Issues, открытые файлы или код. Поскольку Firecrawl расходует кредиты, выставьте ограничение бюджета в кабинете Firecrawl и при необходимости снизьте переменную `FIRECRAWL_MAX_REQUESTS` (по умолчанию 15 запросов за запуск, шесть запусков в сутки).


### Быстрое ручное заполнение

Для разового запуска задайте `all=true`, `limit=150`. Кнопка запуска обработает первые 150 оставшихся без описания книг. Для плановых запусков используйте `all=false` (шардирование 64 групп, с ротацией по времени UTC).

## Конфигурация

| Переменная/секрет | Значение |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Обязательно: JSON служебного аккаунта Google |
| `BOOK_DESCRIPTIONS_ENABLED` | Необязательная переменная: `false` приостанавливает расписание, `true`/отсутствие разрешают запуск |
| `FIRECRAWL_API_KEY` | Обязательно при включённом Actions: ключ официального облачного Firecrawl |
| `FIRECRAWL_MAX_REQUESTS` | Необязательная GitHub Variable: максимум Firecrawl API-запросов за запуск (по умолчанию 220) |
| `FIRECRAWL_BASE_URL` | Жёстко задан официальный облачный адрес `https://api.firecrawl.dev/v2` в Actions |
| `OPENROUTER_API_KEY` | Дополнительно, включает краткий редакционный пересказ |
| `OPENROUTER_MODEL` | По умолчанию `google/gemini-2.5-flash-lite` |
| `MAX_BOOKS` | До 150 веб-карточек за запуск |
| `SHARDS` | 64 независимых группы |
| `USE_BROWSER` | `true`: Playwright Chromium при неудаче других способов |

**Стоимость:** GitHub-hosted runners в общедоступных репозиториях обычно предоставляются без оплаты стандартного времени, но Firecrawl и OpenRouter могут тарифицироваться отдельно. Не публикуйте учётные ключи даже в общедоступном репозитории: используйте Secrets. Не создавайте открытый доступ на запись к самой Google-таблице.

## Локальная проверка

```bash
python -m pip install -r book_descriptions/requirements.txt
python -m unittest discover -s book_descriptions/tests -v
export GOOGLE_SERVICE_ACCOUNT_JSON="$(cat service-account.json)"
python book_descriptions/collector.py --dry-run --limit 20 --all
```

## Принципы качества

- Источником считается только реальная карточка книги или сопоставленное, уже имеющееся в базе описание.
- Аннотация не создаётся из одного названия, рейтинга, пользовательских оценок или догадок.
- При недоступности источника ячейка остаётся пустой для последующего запуска.
- У каждого добавленного описания есть URL источника в соседнем столбце.
- Для листа без столбцов описания и источника эти столбцы создаются **только если на листе есть настоящие карточки книг**.
- Рекламные описания магазинов, SEO-заголовки, метаданные о ценах и отзывах автоматически отбрасываются. Ограничения доступа и robots.txt/правила сайтов необходимо соблюдать; обход защит, требующих авторизации или антибот-проверок, не предусмотрен.
